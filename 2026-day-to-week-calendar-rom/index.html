2026 Day-to-Week Calendar Calculator

Description: This tells you the day of the week. Input your month, input your day, and it will tell you if it landed on a Sunday, Monday, Tuesday, Wednesday, Thursday, Friday, or Saturday in 2026. If the date does not exist (like February 30), an invalid LED turns on instead.

AI Use:

I used AI to help write this page and the website code.

Importance and Topic:

This topic fulfills programmable memory since the lookup table is essential to simplifying such massive equations. A 27C010 EPROM is emulated on a Basys 3 FPGA, and the inputs and outputs are wired on a breadboard.

Inputs/Outputs:

There are 9 inputs and 8 outputs. Four switches select the month and five switches select the day. Each output is one LED.

Inputs:

D4, D3, D2, D1, D0Switches (5)Day, 00001 = 1 to 11111 = 31; D4 is the MSB

Specifications:

A user must be able to enter a month and a day. For example, 1100 01000 would be December 8, and the circuit should spit out the day of the week on its LED. So F7F6F5F4F3F2F1F0 = 0000 0100 (04 in hex). That shows that F2, for Tuesday, is on.

So that means the first step is finding a minterm equation. The month is the top 4 bits and the day is the bottom 5 bits, so the minterm number is 32 × month + day. For example, 1100 01000 in binary is 392. Another example: 0111 00110 (July 6) is 230.

So that means F2 (Tuesday) has 392 as a minterm, and no other LED should turn on. F1 (Monday) has 230 as a minterm, and no other LED should turn on.

The nice part about this is no month has more than 31 days, so the day is exactly 5 bits, from 0 to 31. And 12 months fit in 4 bits.

We can repeat that for every day in the calendar. The easiest way is this: all we need is the first day of the year. 2026 started on a Thursday. So we know 0001 00001 (33) is a Thursday, 0001 00010 (34) is a Friday, 0001 00011 (35) is a Saturday, 0001 00100 (36) is a Sunday, 0001 00101 (37) is a Monday, 0001 00110 (38) is a Tuesday, and so on.

Now we can just add 7 to those values. 0001 00110 (38) is a Tuesday. Add 7 in binary: 0001 01101 (45) is a Tuesday. 0001 10100 (52) is a Tuesday, and 0001 11011 (59) is a Tuesday. When adding 7 runs past the end of the month, it wraps into the next month: January 27 + 7 days is February 3, 0010 00011 (67), which is a Tuesday.

These equations are too big to implement with digital logic chips (343 product terms even after minimizing). However, ROM can simplify this for us. Inside the ROM, a decoder already makes every minterm from 0 to 511, so we never have to minimize. We only choose which minterms turn on each LED.

ROM Implementation:

Each minterm corresponds with a CELL. We only want ONE LED to be on at a time, so every cell holds a power of 2: 1, 2, 4, 8, 16, 32, 64, 128 (01, 02, 04, 08, 10, 20, 40, 80 in hex).

Now we can implement it in ROM. The row is the upper hex digits of the cell and the column is the last hex digit. For example, December 8 is cell 392 = 188 hex, so it is row 180, column 8, which holds 04 (Tuesday). Each month takes two rows: one for days 0–15 and one for days 16–31. Every cell that is not a real date holds 80 (invalid).

Why an FPGA? I didn’t have a 27C010 chip or an EPROM programmer, and I am familar with FPGAs. I used the Artix-7 FPGA on a Basys 3 board as a stand-in for a 27C010 EPROM. My Verilog module is similar to the real chip: 9 address inputs, 8 data outputs, and its contents come from a 512-line file (calendar2026.mem). Each Address is now a line number and it is same bytes I would program into a real EPROM. Only the memory is inside the FPGA; the switches and LEDs are on the breadboard and connect through the board’s Pmod ports. An FPGA is programmable logic, which is this project’s topic, and swapping in a real EPROM later would change the chip, not the design.

calender_top.v

module calendar_top (
    input  [3:0] month,
    input  [4:0] day,
    output [7:0] leds,
    // board leds used for debugging 
    output [7:0] board_leds,
    // these are uses to drive the 7segment displays off to stop the problem of the display growing dimly 
    output [3:0] an,
    output [6:0] seg,
    output dp
);
    wire [8:0] address;
    wire [7:0] data;
    assign address = {month, day};
    rom27c010 eprom (address, data);
    assign leds       = data;
    // board leds used for debugging
    assign board_leds = data;
    assign an  = 4'b1111;
    assign seg = 7'b1111111;
    assign dp  = 1'b1;
endmodule

// A 27C010 EPROM stand-in on the Basys 3.
// This design only uses the first 512 bytes (A8-A0);
// A16-A9 are tied low.
module rom27c010 (
    input  [8:0] A,      // A8-A5 = month, A4-A0 = day (from breadboard switches)
    output [7:0] Q       // Q0 Sun ... Q6 Sat, Q7 invalid date (to breadboard LEDs)
);

    reg [7:0] mem [0:511];                   // the 512 bytes of the chip that are used
    initial $readmemh("calendar2026.mem",mem);// the same bytes a real EPROM would hold

    assign Q = mem[A];                            
endmodule

Video Demo:

Schematics (KiCad): Basys 3 is powered and programmed from the PC through its micro-USB port. The board supplies the FPGA’s core power, 3.3 V, GND and configuration.

Internal pull down resistors are used by the board so I did not use pull-down resistors for the switch inputs.

Basys 3 Reference Manual – Digilent Reference

I used this table from the reference manual to wire up the board.

JA1–JA4, JA7–JA10 → J1, L2, J2, G2, H1, K2, H2, G3 → 8 LEDs (F0–F7)
JB1–JB4, JB7–JB10 → A14, A16, B15, B16, A15, A17, C15, C16 → D0–D4 and M0–M2
JC1 → K17 → M3
JC2–JC10 and all of JXADC: not used

Board: Digilent Basys 3
Chip: AMD (Xilinx) Artix-7 XC7A35T-1CPG236C, a 236-pin package. KiCad splits its 236 pins into units by bank/job so only 2 banks were used.

Basys 3 is powered and programmed from the PC through its micro-USB port. It is not part of the circuit I built since I know need to plug in the cable.
