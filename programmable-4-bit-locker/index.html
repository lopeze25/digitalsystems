Programmable 4-Bit Locker

This is a programmable four-button locker. You press RESET, type a 4-letter code with the A, B, C, and D buttons, and press ENTER to save it. From then on, typing that same code and pressing ENTER turns on the UNLOCK LED. If you mistype a letter, BACKSPACE erases it, just like a phone keypad.
Link to project: (Circuit verse):

https://circuitverse.org/users/425489/projects/4-bit-programmable-locker

The locker can:

  • Save a new 4-letter code after RESET.
  • Unlock only when the exact code is typed, in order.
  • Erase the last letter with BACKSPACE.
  • Lock again as soon as any letter is pressed.

Importance and Topic:

The inspiration for this project came from keypads on doors, safes, and ATMs, and the lock screen on a phone. They all let you type a code, fix a mistake, and only open on the exact sequence. Before keypads, combination locks were mechanical; now almost every one is a small digital circuit that stores what was typed and compares it to a saved code.

This project fulfills the registers topic because a lock is mostly memory: the letters typed, in order, and the saved code. The entry register shifts right when a letter is typed and shifts left on BACKSPACE, the saved-code register loads all 8 bits at once, and both hold the rest of the time. Those are the four operations of a universal shift register like the 74194: hold, shift right, shift left, and parallel load.

Inputs/Outputs:

There are 7 inputs, a clock, and 1 output. Four buttons are the letters, three buttons control the lock, and one LED shows when it is unlocked.

Inputs:

Letter code: A = 00, B = 01, C = 10, D = 11. A 4-letter code is 8 bits, so there are 44 = 256 codes.

Specifications:

The locker must remember the letters in the order they were typed, let the user erase the last one, save a code once, and decide whether a new entry matches it. Order matters: B D A C and B A D C use the same letters but are different codes. The system is broken into four subcomponents, each answering one design question:

SubcomponentDesign questionImplementation
Button inputHow does one press become one letter?Priority encoder (2-bit letter code and KEY) and edge detectors (one pulse per press)
Entry memoryHow are the letters remembered in order and edited?Entry register P0–P3: shift right on a letter, shift left on BACKSPACE, clear on ENTER. A valid register V0–V3 tracks how many letters are in.
Code memoryHow is the code set and kept?Set-mode flip-flop M and a saved-code register S0–S3 that loads all 8 bits once
DecisionDoes the entry match, and how long does it stay open?XNOR compare (MATCH) and an unlock latch U

Every press is handled in one clock cycle. Each button maps to one register operation, and four operations fit in two control bits, S1S0, which drive the entry and valid registers together:

User actionS1S0Register operation
Nothing00Hold
Letter01Shift right (new letter into P0)
BACKSPACE10Shift left (newest letter erased)
ENTER11Clear (load 00 into every slot)

Example: after RESET, typing B D A C fills the register as P0 = C, P1 = A, P2 = D, P3 = B (P0 is always the newest letter). ENTER copies all 8 bits into the saved-code register and ends set mode. Later, typing B D A D, BACKSPACE, C puts C A D B back in P, ENTER finds every slot equal to the saved code, and the LED turns on. Pressing A turns it off.

Design Choices:

The design came together one problem at a time. Each problem below changed the design and led to the next decision.

1. Remembering the order. The first question was how to store a code where order matters. We considered giving each letter a fixed slot and using a counter and decoder to point at the next empty one. A shift register does the same job with no pointer: every new letter enters P0 and the older ones move over one place. So the entry is a 4-slot, 2-bit shift register.

2. One press filled every slot. When we tested it, one press of B filled all four slots with B B B B. The clock is much faster than a finger, so the register shifted on every clock while the button was held. Each button now goes through an edge detector (one flip-flop and one AND gate) that makes a pulse exactly one clock long.

3. Two buttons at once made a letter nobody pressed. With a plain encoder, B (01) and C (10) pressed together read as 11, which is D. A priority encoder outputs the higher button instead, so the code is always a real letter, and its Valid output gives KEY for free instead of a 4-input OR gate.

4. A SET/UNLOCK switch overwrote the code. The first version had a switch for set mode. If someone left it on SET, every ENTER saved a new code. We replaced the switch with one flip-flop, M. RESET sets it, and the first save clears it by itself, so RESET is the only way back into set mode.

5. Saving the code. When ENTER is pressed in set mode, the code is already sitting in P in the right order, so the saved-code register loads all 8 bits in parallel on one clock. Shifting it in again would have meant typing it twice.

6. ENTER alone unlocked it again. After the owner unlocked it, the old code was still in P, so anyone could press ENTER with nothing typed and it unlocked. ENTER now clears the entry register.

7. The clear erased the code before it was used. Our first clear used the flip-flops’ asynchronous clear pin. ENT stays high for a whole clock, so P was wiped right away, before the saved-code register and the compare read it. The clear now goes through the register’s input logic, so everything reads the old P on the clock edge and P becomes 00 on that same edge.

8. Typos and BACKSPACE. Adding BACKSPACE meant the register also had to shift left. Now each slot needs four operations: hold, shift right, shift left, and clear. That is exactly one 74194 cell: a 4 to 1 MUX in front of a D flip-flop, with one 2-bit control, S1S0. Clear uses the load input with 00, so it costs no extra mode. Hold comes from feeding each slot’s output back into the MUX. The other option, gating the clock like Lab 12 Circuit 3, can create a false clock edge if a control signal changes while the clock is high.

9. A fifth letter could not be erased. A fifth letter pushed the oldest one off the end, and BACKSPACE could not bring it back. So the lock has to know how many letters are in. An up/down counter would work, but counters are their own topic and it needs extra logic to count both ways and decode “4.” Instead, a valid register uses the same cell: a letter shifts in a 1, BACKSPACE shifts in a 0, and it fills like a thermometer. Four letters is one wire, V3, and a letter is ignored once V3 = 1.

10. An empty entry unlocked a code of AAAA. An empty entry register reads 00 00 00 00, which is A A A A. If the saved code was AAAA, ENTER alone unlocked it, and ENTER after three letters could save a 3-letter code. The valid register fixes both: MATCH needs V3 = 1, and saving needs ENT4 = ENT·V3.

11. The LED only flashed. Driving the LED straight from MATCH did not work: ENTER clears P on the same clock, so MATCH drops right away and the LED was on for one clock. The unlock latch U stores the result on ENTER and holds it until a letter is pressed.

12. Comparing the codes. We only need equal or not equal, never greater or less than, so a magnitude comparator is more than needed. One XNOR per bit and one AND gate give MATCH.

4. Entry Register (P0–P3)

Each slot is a 2-bit register with a 4 to 1 MUX on its input (one 74194 cell). Pk−1 is the newer slot and Pk+1 is the older slot. For P0, Pk−1 is the letter code b1b0. For P3, Pk+1 is 00.

9. Unlock Latch U

U stores MATCH on LU, clears on any letter, and holds otherwise.

LUPRESSU+Operation
1×MATCHUnlock if equal
010Lock again
00UHold

m = 8·LU + 4·PRESS + 2·MATCH + U.

PI1: LU·MATCH (EPI). PI2: LU′PRESS′U (EPI).

U+ = LU·MATCH + LU′PRESS′U

U only changes on LU or PRESS, so the flip-flop’s enable does the hold: EN = LU + PRESS and D = LU·MATCH. When PRESS loads, LU = 0, so D = 0. U drives the UNLOCK LED through a 330 Ω resistor.
