Five-Person Telephone Exchange

This is a five-person telephone exchange. Each telephone (A–E) can call another, switch to a different one, or hang up, and calls already connected stay connected.
Link to project: (CircuitVerse):

https://circuitverse.org/users/425489/projects/five-person-telephone-exchange/simulator/embed

How to use it:

  1. Press RESET. Every display shows 0 (free) and every busy LED is off.
  2. Set the caller on switches S2–S0 and the telephone being called on D2–D0 (001 = A, 010 = B, 011 = C, 100 = D, 101 = E).
  3. Press CLK. Each telephone's display shows its partner's number and both busy LEDs turn on. If the ERROR star is lit, the call is rejected (busy or calling itself).
  4. To switch, call someone new: the old partner is disconnected on the same press.
  5. To hang up, set D2–D0 to 000 and press CLK.

Importance and Topic:

Telephone switches in offices, hotels, and hospitals route each call to the right line. Operators did this by hand in the 1870s; Bell's 1ESS automated it in 1965. This fulfills the MUX/DEMUX topic: MUXes read the state of a selected telephone, and DEMUXes select which telephones are updated.

Specifications:

Each telephone has a 3-bit register that stores its partner's code (000 if free). One CLK press must check the call, connect both telephones, and disconnect the caller's old partner.

Example: A is connected to C and calls B. On CLK, A loads 010 (B), B loads 001 (A), and C loads 000, so C is free again.

Problems Encountered leading to Design Choices:

1. Each telephone stores its partner's number. I compared this with one flip-flop per pair of telephones (10 pairs). Storing the partner's code lets the display show it directly and makes finding the old partner one MUX read.

2. One shared read MUX and busy MUX. The switches select which telephone is read, so adding a telephone adds a MUX input instead of a new circuit.

3. One clock edge per call. The old partner is read before the edge, so the clear and both writes happen on the same edge. A two-step version would need a temporary register.

4. Clearing through the register MUX. My first version cleared through the flip-flop reset pin, which acted immediately and cut calls while I was still setting the switches. Through the MUX, the clear waits for CLK like every other update.

5. 000 means free and hang up. A cleared register already reads as free, and dialing 000 hangs up with one OR gate: WRITE = ACCEPT + Z0.

6. Busy is the OR of the register bits. My separate busy flip-flop stayed on after a hang-up. The OR can never disagree with the register.

7. MUXes read, DEMUXes write. Reading one telephone is many-to-one and writing one is one-to-many. The DEMUX data input acts as the enable (ACCEPT or WRITE), so no extra AND gates are needed.

8. SAME check as a DEMUX and MUX pair. Two parts instead of three XNORs and an AND, and the DEMUX's 000 output (Z0) detects a hang-up for free.

Derivations:

Each derivation matches a block in Figure 1. MUX implementations use the control-bit method of Section 10.2.4 (shading); the registers follow Section 12.3.1 (D flip-flops, so each flip-flop input equals the next state).

1. Clock and Reset Buttons

No logic. CLK drives every flip-flop's clock, so all updates share one rising edge. RESET drives every flip-flop's reset, so every register starts at 000.

2. Source and Destination Switches

No logic. Each group of three switches is one telephone code (see Inputs).

3. Read MUX

Select = S. Input Im = register of telephone m (3 bits).

P = S2′S1′S0(QA) + S2′S1S0′(QB) + S2′S1S0(QC) + S2S1′S0′(QD) + S2S1′S0(QE)

4. Busy MUX

Select = D. Input Im = busy signal of telephone m. Unused codes are tied to 1 so they read as busy.

BUSY = D2′D1′D0′(1) + D2′D1′D0(BUSYA) + D2′D1D0′(BUSYB) + D2′D1D0(BUSYC) + D2D1′D0′(BUSYD) + D2D1′D0(BUSYE) + D2D1D0′(1) + D2D1D0(1)

6. Three DEMUXes

Zk = mk(select)·I. Z1–Z5 go to telephones A–E; Z0, Z6, and Z7 are unused.

The destination and clear DEMUXes are the same, with the select and data from the table.

Example: A (connected to B) calls C. S = 001, D = 011, P = 010. On CLK: WSA → A loads 011; WDC → C loads 001; CLRB → B loads 000.

7. Telephone Registers and Busy ORs

Each register is a 3-bit PIPO register with control logic on each flip-flop input (Section 12.1.4). Controls CLR, WS, and WD come from the DEMUXes.

1. Transition table. Current state Qk (bit k of the register); inputs Sk, Dk; controls CLR WS WD. With D flip-flops, the flip-flop input equals Qk+.

CLR WS WDQk+Operation
000QkHold
001SkCalled: load the caller's number
010DkCaller: load the dialed number (000 hangs up)
1000Clear (old partner)
011, 101, 110, 111×Cannot occur (at most one control is 1)

2. Next-state expression. The control bits are the MUX select lines (Section 10.2.4), so each control row is one MUX input:

Qk+ = CLR′WS′WD′(Qk) + CLR′WS′WD(Sk) + CLR′WS·WD′(Dk) + CLR·WS′WD′(0)

One 8 to 1 MUX per flip-flop, select CLR WS WD: I0 = Qk, I1 = Sk, I2 = Dk, I3–I7 = 0. No external gates.

3. Busy output. BUSY = 1 when the register is not 000; 110 and 111 are never stored (×).

PI1: Q2 (EPI). PI2: Q1 (EPI). PI3: Q0 (EPI).

BUSY = Q2 + Q1 + Q0

8. Displays and LEDs

No logic beyond wiring: each hex display shows its register with a leading 0 (0–5), each busy LED shows BUSY = Q2 + Q1 + Q0, and the star shows ERROR.
